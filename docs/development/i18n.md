# Internationalization

Yamabiko Table Reorder の翻訳ファイルは `languages/` で管理します。

## 生成フロー

TypeScript の翻訳文字列は、通常の `@wordpress/scripts` build とは分離した専用の Babel CLI で抽出します。`@wordpress/babel-plugin-makepot` で TypeScript の source reference を保持した一時 POT を生成し、WP-CLI で PHP 側の翻訳文字列と統合します。

```bash
npm run i18n
```

このコマンドは次の順に実行されます。

1. `npm run i18n:extract-js` で `src/editor-extensions/table-reorder/messages.ts` から一時 POT を生成
2. `wp i18n make-pot --skip-js --merge` で `yamabiko-table-reorder.php` の翻訳文字列と一時 POT を統合し、`languages/yamabiko-table-reorder.pot` を生成
3. `wp i18n update-po` で既存の日本語訳を維持しながら PO を POT に同期
4. `wp i18n make-json` の `--use-map` で TypeScript の source path を実行時の `build/editor-extensions/table-reorder/index.js` に対応付け、WordPress が読み込む Jed JSON を生成
5. 生成した JSON を Prettier でプロジェクトのフォーマットに揃える

TypeScript 抽出を通常 build から分離しているのは、webpack の `babel-loader` cache によって Makepot plugin の出力処理が省略されることを避け、常に同じ手順で翻訳文字列を再生成できるようにするためです。

POT では `src/editor-extensions/table-reorder/messages.ts` を source reference として保持し、Jed JSON の生成時だけ `--use-map` で実行時 JavaScript のパスへ対応付けます。これにより、TypeScript を翻訳ソースの正本としつつ、`wp_set_script_translations()` が実際に読み込むスクリプトに対応した hash 付き JSON を生成できます。

## ファイルの役割

- `languages/yamabiko-table-reorder.pot`
  - 翻訳対象文字列のテンプレートです。
  - ソースコードから再生成できます。
- `languages/yamabiko-table-reorder-ja.po`
  - 日本語翻訳の正本です。
  - `msgstr` の日本語訳はこのファイルで維持します。
- `languages/yamabiko-table-reorder-ja-<hash>.json`
  - JavaScript 実行時に WordPress が読み込む生成物です。
  - ファイル名の hash は翻訳対象 JavaScript の相対パスから WP-CLI が生成します。

## Git 管理

POT / PO / JSON はすべて Git 管理対象です。

- POT は翻訳対象の変更をレビュー可能にするためコミットします。
- PO は日本語訳の正本なので必ずコミットします。
- JSON は配布 ZIP に含まれる実行時成果物なのでコミットします。
- Babel 抽出時の一時 POT / JavaScript は Git 管理せず、生成処理の最後に削除します。
- `build/` 自体は引き続き Git 管理対象外です。

翻訳文言を追加・変更した場合は `npm run i18n` を実行し、POT / PO / JSON の差分をまとめて確認してください。
