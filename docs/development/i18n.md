# Internationalization

Yamabiko Table Reorder の Production 翻訳は WordPress.org Language Pack を使用します。

リポジトリでは、翻訳対象文字列のテンプレートと、開発中の未リリース文字列をローカルで日本語確認するための開発専用翻訳だけを管理します。

```text
Production
WordPress.org Language Pack

Development
languages/yamabiko-table-reorder.pot
 ↓
dev/i18n/yamabiko-table-reorder-ja.po
 ↓
dev/i18n/generated/
 ↓
ローカル WordPress
```

## Production: POT 生成

TypeScript の翻訳文字列は、通常の `@wordpress/scripts` build とは分離した専用の Babel CLI で抽出します。`@wordpress/babel-plugin-makepot` で TypeScript の source reference を保持した一時 POT を生成し、WP-CLI で PHP 側の翻訳文字列と統合します。

```bash
npm run i18n
```

`npm run i18n` は `npm run i18n:pot` のエイリアスです。次の順に POT を更新します。

1. `npm run i18n:extract-js` で `src/messages.ts` から一時 POT を生成
2. `wp i18n make-pot --skip-js --merge` で `yamabiko-table-reorder.php` の翻訳文字列と一時 POT を統合
3. `languages/yamabiko-table-reorder.pot` を更新
4. 一時 POT / JavaScript を削除

TypeScript 抽出を通常 build から分離しているのは、webpack の `babel-loader` cache によって Makepot plugin の出力処理が省略されることを避け、常に同じ手順で翻訳文字列を再生成できるようにするためです。

POT では `src/messages.ts` を source reference として保持します。Production の実行時翻訳ファイルはリポジトリ内で生成・同梱せず、WordPress.org Language Pack に委ねます。

JavaScript 翻訳は `wp_set_script_translations( $handle, 'yamabiko-table-reorder' )` により WordPress 標準の Language Pack 探索経路から読み込みます。プラグイン内の `languages/` は実行時翻訳ファイルの読み込み先として使用しません。

## Development: 開発時の日本語確認

開発中の新しい翻訳対象文字列は、WordPress.org Language Pack が生成される前でも `dev/i18n/` の開発専用翻訳で確認できます。

### 1. 開発用翻訳を同期する

```bash
npm run i18n:dev
```

このコマンドは次を行います。

1. POT を最新化
2. `dev/i18n/yamabiko-table-reorder-ja.po` を POT に同期
3. JavaScript 用 Jed JSON を `dev/i18n/generated/` に生成
4. PHP 用 MO を `dev/i18n/generated/` に生成

新しい msgid が追加された場合は、`dev/i18n/yamabiko-table-reorder-ja.po` の空の `msgstr` に確認用の日本語訳を追加し、次を実行して成果物だけ再生成します。

```bash
npm run i18n:dev:artifacts
```

`dev/i18n/generated/` は Git 管理対象外で、`package.json` の配布対象にも含まれません。開発用 JSON / MO を `languages/` へ生成しないでください。

### 2. ローカル WordPress へ配置する

ローカル WordPress の `wp-content/languages/plugins/` を `WP_PLUGIN_LANG_DIR` で指定し、生成済みの JSON / MO を配置します。

```bash
WP_PLUGIN_LANG_DIR=/path/to/wp-content/languages/plugins npm run i18n:dev:install
```

このスクリプトは、次のファイルだけを指定先へコピーします。

- `yamabiko-table-reorder-ja.mo`
- `yamabiko-table-reorder-ja-<hash>.json`

個人のローカルパスはリポジトリへ記録しません。ローカル WordPress 環境の実際のパスは、その環境のドキュメントに従って指定してください。

### 3. UI と announcement を確認する

日本語 locale の WordPress で、変更した UI を実際に操作して確認します。

- 表示されるラベル、説明、notice、dialog
- Row / Column / Reorder Form の各メッセージ
- 操作結果や失敗時の notice
- screen reader 向け accessibility announcement など、画面に常時表示されない文字列

JavaScript 翻訳は hash 付き JSON が `build/index.js` に対応しているため、`npm run build` 後のプラグインを同じローカル WordPress で使用して確認します。

## Language Pack 経路の互換性確認

`wp_set_script_translations()` の第3引数を指定せず WordPress 標準の Language Pack 探索経路を使用するため、i18n 経路を変更した場合は最低対応の WordPress 6.8 を含む環境で確認します。

`npm run i18n:dev:install` で配置する開発用 MO / JSON は、WordPress.org Language Pack と同じ `wp-content/languages/plugins/` に同じ命名規則で配置されます。そのため、Language Pack 経路の確認では開発用翻訳が残った状態を使用しないでください。

確認手順:

1. `i18n:dev:install` で配置した YTR の開発用 MO / JSON が `wp-content/languages/plugins/` に残っていないことを確認する。
2. WordPress.org から YTR の日本語 Language Pack を取得し、Language Pack の MO / JSON が配置された状態にする。
3. 配置されている YTR の翻訳ファイルが、開発用生成物ではなく WordPress.org から取得した Language Pack であることを確認する。
4. その状態で、最低対応の WordPress 6.8 を含む確認環境から主要 UI と JavaScript 翻訳を確認する。

確認対象:

- WordPress.org Language Pack 経由で JavaScript 翻訳が読み込まれること
- 主要 UI が日本語表示されること
- accessibility announcement を含む翻訳対象文字列が期待どおり表示・通知されること

開発用翻訳を再度確認する場合は、この Language Pack 経路確認とは分けて `npm run i18n:dev:install` を使用します。

## 配布物への混入確認

開発用翻訳はリリース成果物へ含めません。配布前または i18n フロー変更時には次を実行します。

```bash
npm run plugin-zip
```

生成された ZIP を確認し、`dev/i18n/`、開発用 PO、開発用 JSON / MO が含まれていないことを確認してください。

`package.json` の `files` に `languages/` は含まれますが、Production で同梱するのは POT のみです。`dev/` は配布対象外です。

## ファイルの役割

- `languages/yamabiko-table-reorder.pot`
  - 翻訳対象文字列のテンプレートです。
  - ソースコードから再生成し、Git 管理します。
  - WordPress.org への翻訳元および開発用 PO の同期元として使用します。
- `dev/i18n/yamabiko-table-reorder-ja.po`
  - 開発中の未リリース文字列を日本語で確認するための専用 PO です。
  - WordPress.org Language Pack の代替配信手段ではありません。
  - Git 管理します。
- `dev/i18n/generated/`
  - 開発確認用 JSON / MO の一時生成先です。
  - Git 管理せず、配布 ZIP にも含めません。

Production 用の日本語 PO / JSON はリポジトリで管理・生成しません。翻訳の配信は WordPress.org Language Pack に一本化します。
