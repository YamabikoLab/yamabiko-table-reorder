# Reorder v1 基本設計書

## 1. 目的

本書は、`docs/requirements/reorder-v1-requirements.md`および`docs/requirements/reorder-v1-quality-requirements.md`で定義した正式v1の要件のうち、行・列のどちらにも属さない共通の利用者向け設計を定義する。

行並び替え固有の設計は`row-reorder-v1-design.md`、列並び替え固有の設計は`column-reorder-v1-design.md`で定義する。

Keyboard操作、ドラッグを必要としない操作、focus、announcement、支援技術への情報提供など、別要件として扱うアクセシビリティ設計は本書の対象外とする。

## 2. 基本方針

- 通常のTable編集と並び替え操作を、利用者が見分けられるようにする。
- 「行を並び替え」と「列を並び替え」の2つの明示的な並び替えモードを設ける。
- 行並び替えモードでは行の並び替えだけを、列並び替えモードでは列の並び替えだけを開始できるようにする。
- DnD開始時は、現在の移動対象を線で囲み、DnDが開始されたことと移動対象を確認できるようにする。
- 並び替えはセル内容の種類に依存せず、内容そのものを変更せずに位置だけを変更する。
- DnD中は、現在どこへ移動する操作なのかを挿入線で確認できるようにする。
- DnD中はTable上の実際の順番を変更せず、移動対象、移動先、周囲の表示を更新する。
- 移動先が変わった場合は、移動対象が入る空間を空けるように、位置が変わる周囲を滑らかに移動させる。
- ドラッグ中の移動対象は、元のTable上での大きさと配置関係を保って表示する。
- 並び替えが成立した場合だけTableの順序を更新する。

## 3. 並び替えモードと入口

通常時はTableの編集を行う状態とし、並び替え操作は有効にしない。

Tableのツールバーに「行を並び替え」と「列を並び替え」の入口を表示する。これらは並び替えモードへ切り替えるための操作であり、ドラッグ対象となるhandleではない。

「行を並び替え」を選択すると行並び替えモードになり、「列を並び替え」を選択すると列並び替えモードになる。選択していない方向の並び替え操作は開始しない。

選択中の並び替え入口は、利用者が現在のモードを確認できるよう、通常時と明確に区別できる選択状態として視覚的に強調する。「行を並び替え」と「列を並び替え」は排他的に選択し、一方を選択した場合はもう一方を非選択状態にする。並び替えモードを終了すると通常のTable編集へ戻り、どちらの入口も非選択状態にする。

各入口には、次のツールチップを表示する。

| 入口 | 日本語 | English |
| --- | --- | --- |
| 行並び替えモード | 行を並び替え | Reorder rows |
| 列並び替えモード | 列を並び替え | Reorder columns |

### 3.1 初回案内

初めて利用する人が行・列を並び替えられることを認識できるよう、初回案内を表示する。

PCでは、Tableにポインターを重ねた場合、Tableがフォーカスされた場合、またはセル編集が開始された場合に、その操作環境で初回案内がまだ表示されていなければ、Tableのツールバーの下に案内を表示する。

タッチ端末では、Tableがフォーカスされた場合、またはセル編集が開始された場合に、その操作環境で初回案内がまだ表示されていなければ、Tableのツールバーの下に案内を表示する。

PCでは、Tableからポインターが外れたことだけでは初回案内を終了しない。

初回案内は、利用者についてPCとタッチ端末のそれぞれで一度だけ表示する。PCで初回案内を表示済みであっても、タッチ端末で初めて利用する場合は初回案内を表示する。

案内文は次のとおりとする。

- 日本語: `行と列を並び替えられます。`
- English: `Reorder rows and columns.`

初回案内の表示中は、「行を並び替え」と「列を並び替え」の両方の入口を通常時より視覚的に強調し、利用者がどこから並び替えを開始できるか確認できるようにする。

利用者がいずれかの入口を選択した場合、または初回案内を閉じた場合は、初回案内と入口の強調表示を終了し、その操作環境では表示済みとして扱う。

初回案内は通常のセル編集を妨げない。どの操作箇所へfocusを移すかなど、focusの具体的な扱いはアクセシビリティ設計で定義する。

### 3.2 再案内

初回案内を表示済みでも、利用者が並び替え機能を忘れている可能性があり、通常編集状態で行または列を移動しようとしていると判断できる操作が繰り返された場合は、並び替えの入口を再案内する。

再案内の契機は、セル内容の編集、文字選択、通常スクロールなどとして成立しない、行または列を移動しようとするドラッグ操作が、同じ行または列の付近で短時間に繰り返された場合とする。一度だけの短いドラッグや通常の編集操作では再案内しない。

再案内では、Tableのツールバーの下に案内を表示し、「行を並び替え」と「列を並び替え」の入口を確認できるようにする。

再案内は通常のTable編集を妨げず、同じ状況で過度に繰り返し表示しない。

## 4. DnD中の共通表示

DnDが開始されたら、現在の移動対象を線で囲み、DnDが開始されたことと移動対象を視覚的に示す。

DnD中はTable上の実際の順番を変更せず、現在の移動先を挿入線で示す。移動先が変わると、挿入線も現在の移動先へ移る。

移動先が変わった場合は、移動対象が入る空間を空けるように、実際に表示位置が変わる周囲の行または列を滑らかに移動させる。位置が変わらない行または列は、この移動に合わせて一斉に動かさない。

ドラッグ中の移動対象は、空のセルを含んでいても元のTable上にあるときの大きさやセルの配置関係が不自然に崩れないように表示する。表示範囲の制約によって、移動に必要な自動スクロールは妨げない。

方向ごとの移動先、構造保持、自動スクロール、および移動対象の表示範囲は、行・列それぞれの基本設計書で定義する。

## 5. 確定・キャンセル

有効な移動先でDnDが完了した場合だけ、その時点でTableの順序を更新する。確定時は、移動対象を最終位置へ滑らかに移動させ、並び替え後の配置へ自然につなげる。

操作がキャンセルされた場合は、移動対象を元の位置へ自然に戻し、Tableのデータを変更しない。

移動先が成立しない場合、または有効な位置へドロップされなかった場合も、Tableのデータを変更しない。

## 6. 継続できない場合の安全な終了

DnD中にEditorやTableの状態が変化して並び替えを継続できなくなった場合、またはReorderの処理中にエラーが発生した場合は、その並び替え操作を終了する。

終了時は、移動対象の強調、挿入線、周囲の移動表示などDnD中だけの表示を解除し、利用者がその時点のTableの状態から通常の編集を続けられる状態へ戻す。

継続できなくなった操作を新たに並び替え結果として確定しない。Tableの更新がすでに反映された後に操作を継続できなくなった場合は、終了処理によってその更新を自動的に元へ戻さず、その時点のTableの状態から編集を継続できるようにする。

異常状態の分類、検出、復旧方法、記録など、内部での具体的な実現方法はArchitectureで定義する。

## 7. 並び替え後の共通状態

並び替えが成立した場合、移動した行または列の位置だけを変更し、セルの内容、属性、装飾その他の保持すべき情報は維持する。

セル内容がテキスト、画像、RichTextその他の内容であっても、並び替えの扱いは変えない。セル内容そのものは変更せず、位置だけを変更する。

`FR-13`で定義する対応Table Blockのいずれでも、利用者から見た操作と結果は同じ方針とする。

一回の並び替えは、一回のUndo操作で並び替え前の順序へ戻せるようにする。

## 8. 大規模Table

大規模Tableの判定基準、想定最大規模、およびPerformanceの保証範囲は、Quality Requirementsの`QR-01 Performance`に従う。

Tableが大きい場合でも、並び替えの入口、移動対象、現在の移動先を示す挿入線、確定後の結果を確認できる状態を維持する。

移動先が変わったときに滑らかに移動させる対象は、実際に表示位置が変わる行または列とし、無関係な行または列まで一斉に動かさない。
