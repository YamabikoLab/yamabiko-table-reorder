# Reorder v1 基本設計書

## 1. 目的

本書は、`docs/requirements/reorder-v1-requirements.md` で定義した正式 v1 の要件を、利用者から見える画面、操作、状態、メッセージ、振る舞いとして具体化する。

対象は WordPress Core Table と Flexible Table Block の行・列 DnD とする。

Keyboard 操作、ドラッグを必要としない操作、focus、announcement、支援技術への情報提供など、別要件として扱うアクセシビリティ設計は本書の対象外とする。

## 2. 基本方針

- 通常の Table 編集と並び替え操作を、利用者が見分けられるようにする。
- 「行を並び替え」と「列を並び替え」の 2 つの明示的な並び替えモードを設ける。
- 行の並び替えと列の並び替えを、利用者が見分けられるようにする。
- 並び替えモード中は、行または列そのものを並び替え対象として操作できるようにする。
- DnD 中は、現在どこへ移動する操作なのかを挿入線で確認できるようにする。
- DnD 中は Table 上の実際の順番を変更せず、移動対象と移動先を示す表示だけを更新する。
- ドラッグ中の行・列は、元の Table 上での大きさと配置関係を保って表示する。
- 行の DnD では縦方向、列の DnD では横方向だけを移動のための自動スクロール対象とする。
- Table の構造を壊す移動先では、並び替えを成立させない。
- 並び替えが成立した場合だけ Table の順序を更新する。

## 3. 並び替えモードと入口

通常時は Table の編集を行う状態とし、並び替え操作は有効にしない。

Table のツールバーに「行を並び替え」と「列を並び替え」の入口を表示する。これらは並び替えモードへ切り替えるための操作であり、ドラッグ対象となる handle ではない。

「行を並び替え」を選択すると行並び替えモードになり、行そのものを並び替え対象として操作できる。「列を並び替え」を選択すると列並び替えモードになり、列そのものを並び替え対象として操作できる。

利用者が現在どのモードにいるかを確認できるようにする。行並び替えモードと列並び替えモードを切り替えた場合は、選択した側のモードへ切り替わる。並び替えモードを終了すると通常の Table 編集へ戻る。

各入口には、次のツールチップを表示する。

| 入口 | 日本語 | English |
| --- | --- | --- |
| 行並び替えモード | 行を並び替え | Reorder rows |
| 列並び替えモード | 列を並び替え | Reorder columns |

### 3.1 初回案内

初めて利用する人が行・列を並び替えられることを認識できるよう、初回案内を表示する。

Table がフォーカスされた場合、またはセル編集が開始された場合に、その Table で初回案内がまだ表示されていなければ、Table のツールバーの下に案内を表示する。

案内文は次のとおりとする。

- 日本語: `行と列を並び替えられます。`
- English: `Reorder rows and columns.`

初回案内は通常のセル編集を妨げない。どの操作箇所へ focus を移すかなど、focus の具体的な扱いはアクセシビリティ設計で定義する。

## 4. PC での DnD

### 4.1 行

行並び替えモード中に、利用者が行そのものからドラッグを開始すると、その行を移動対象として扱う。

ドラッグ中は、有効な移動先となる行間に水平の挿入線を表示する。有効な移動先でドロップすると、その位置へ行を移動する。

### 4.2 列

列並び替えモード中に、利用者が列そのものからドラッグを開始すると、その列を移動対象として扱う。

ドラッグ中は、有効な移動先となる列間に垂直の挿入線を表示する。有効な移動先でドロップすると、その位置へ列を移動する。

## 5. タッチ端末での DnD

### 5.1 行

行並び替えモード中は、行そのものを並び替え対象として操作する。

並び替えを開始していない通常操作では、Table や編集画面を通常どおりスクロールできるようにする。行から DnD を開始した後は、有効な移動先となる行間に水平の挿入線を表示する。

有効な移動先で操作を完了すると、その位置へ行を移動する。

### 5.2 列

列並び替えモード中は、列そのものを並び替え対象として操作する。

並び替えを開始していない通常操作では、Table や編集画面を通常どおりスクロールできるようにする。列から DnD を開始した後は、有効な移動先となる列間に垂直の挿入線を表示する。

有効な移動先で操作を完了すると、その位置へ列を移動する。

## 6. DnD 中の表示と移動

### 6.1 ドラッグ中の行・列

ドラッグ中の行・列は、元の Table 上にあるときの大きさとセルの配置関係を保って表示する。

行をドラッグする場合は、空のセルを含んでいても行全体の横幅や各セルの幅が不自然に縮まないようにする。

列をドラッグする場合も、空のセルを含んでいても列全体の幅や各セルの高さが不自然に縮まないようにする。

### 6.2 Preview と移動先

DnD 中は、Table 上の行・列の実際の順番を変更しない。移動対象の表示と、現在の移動先を示す挿入線だけを更新する。

現在の有効な移動先を挿入線で示す。行の並び替えでは行間に水平の挿入線を表示し、列の並び替えでは列間に垂直の挿入線を表示する。移動先が変わると、挿入線も現在の移動先へ移る。

Table の構造を保てる位置だけを有効な移動先として扱う。結合セルなどのために移動すると Table の構造が成立しなくなる位置では、確定可能な移動先を示す挿入線を表示せず、並び替えを確定しない。

### 6.3 自動スクロール

Table が画面内に収まらない場合でも、移動方向に沿って並び替えを続けられるようにする。

行の DnD 中は、行の移動に必要な縦方向だけを自動スクロールし、横方向には自動スクロールしない。

列の DnD 中は、列の移動に必要な横方向だけを自動スクロールし、縦方向には自動スクロールしない。

DnD を開始していない通常状態では、この制限を適用せず、Table や編集画面を通常どおりスクロールできるようにする。

### 6.4 確定

有効な移動先でドロップして DnD が完了した場合だけ、その時点で Table の順序を更新する。

操作がキャンセルされた場合、移動先が成立しない場合、または有効な位置へドロップされなかった場合は、Table のデータを変更しない。

## 7. 並び替え後の状態

並び替えが成立した場合、移動した行または列の位置だけを変更し、セルの内容、属性、装飾その他の保持すべき情報は維持する。

WordPress Core Table と Flexible Table Block のどちらでも、利用者から見た操作と結果は同じ方針とする。

一回の並び替えは、一回の Undo 操作で並び替え前の順序へ戻せるようにする。

## 8. 大規模 Table

大規模な Table でも、利用者が行・列の並び替えを継続して操作できることを前提とする。

Table が大きい場合でも、並び替えの入口、移動対象、現在の移動先を示す挿入線、確定後の結果を確認できる状態を維持する。
