# Reorder v1 基本設計書

## 1. 目的

本書は、`docs/requirements/reorder-v1-requirements.md` で定義した正式 v1 の要件を、利用者から見える画面、操作、状態、メッセージ、振る舞いとして具体化する。

対象は WordPress Core Table と Flexible Table Block の行・列 DnD とする。

Keyboard 操作、ドラッグを必要としない操作、focus、announcement、支援技術への情報提供など、別要件として扱うアクセシビリティ設計は本書の対象外とする。

## 2. 基本方針

- 通常の Table 編集と並び替え操作を、利用者が見分けられるようにする。
- 行の並び替えと列の並び替えを、利用者が見分けられるようにする。
- DnD 中は、現在どこへ移動する操作なのかを画面上で確認できるようにする。
- Table の構造を壊す移動先では、並び替えを成立させない。
- 並び替えが成立した場合だけ Table の順序を更新する。

## 3. 並び替えの入口

対応する Table では、行と列それぞれに並び替えを開始するための操作箇所を表示する。

行の操作箇所と列の操作箇所は、位置と見た目によって区別できるようにする。通常のセル編集領域とは分離し、文字入力やセル選択のつもりで並び替えが始まらないようにする。

初めて利用する人が行・列を並び替えられることを認識できるよう、並び替えの入口を初回利用時に案内する。案内では、行用と列用の操作箇所、およびドラッグして移動する操作であることを確認できるようにする。

## 4. PC での DnD

### 4.1 行

利用者が行の並び替え操作箇所からドラッグを開始すると、その行を移動対象として扱う。

ドラッグ中は、現在の移動先を Table 上で確認できる状態にする。有効な移動先でドロップすると、その位置へ行を移動する。

### 4.2 列

利用者が列の並び替え操作箇所からドラッグを開始すると、その列を移動対象として扱う。

ドラッグ中は、現在の移動先を Table 上で確認できる状態にする。有効な移動先でドロップすると、その位置へ列を移動する。

## 5. タッチ端末での DnD

### 5.1 行

利用者が行の並び替え操作箇所から並び替え操作を開始すると、その行を移動対象として扱う。

並び替えを開始していない通常操作では、Table や編集画面を通常どおりスクロールできるようにする。並び替え操作を開始した後は、ドラッグ中の移動先を画面上で確認できるようにする。

有効な移動先で操作を完了すると、その位置へ行を移動する。

### 5.2 列

利用者が列の並び替え操作箇所から並び替え操作を開始すると、その列を移動対象として扱う。

並び替えを開始していない通常操作では、Table や編集画面を通常どおりスクロールできるようにする。並び替え操作を開始した後は、ドラッグ中の移動先を画面上で確認できるようにする。

有効な移動先で操作を完了すると、その位置へ列を移動する。

## 6. 移動先と確定

DnD 中は、移動対象と現在の移動先を区別して確認できるようにする。

Table の構造を保てる位置だけを有効な移動先として扱う。結合セルなどのために移動すると Table の構造が成立しなくなる位置では、並び替えを確定しない。

有効な移動先で DnD が完了した場合だけ、Table の順序を更新する。操作がキャンセルされた場合、移動先が成立しない場合、または有効な位置へドロップされなかった場合は、Table のデータを変更しない。

## 7. 並び替え後の状態

並び替えが成立した場合、移動した行または列の位置だけを変更し、セルの内容、属性、装飾その他の保持すべき情報は維持する。

WordPress Core Table と Flexible Table Block のどちらでも、利用者から見た操作と結果は同じ方針とする。

一回の並び替えは、一回の Undo 操作で並び替え前の順序へ戻せるようにする。

## 8. 大規模 Table

大規模な Table でも、利用者が行・列の並び替えを継続して操作できることを前提とする。

Table が大きい場合でも、並び替えの入口、移動対象、現在の移動先、確定後の結果を確認できる状態を維持する。
