# Column Reorder v1 基本設計書

## 1. 目的

本書は、正式v1の列並び替えについて、利用者から見える画面、操作、状態、メッセージ、振る舞いを定義する。

並び替えモードの入口、初回案内、共通のDnD表示、確定・キャンセル、安全な終了、Undo、対応Table Block、大規模Tableに関する共通設計は`reorder-v1-design.md`で定義する。

Keyboard操作、ドラッグを必要としない操作、announcement、支援技術への情報提供など、別要件として扱うアクセシビリティ設計は本書の対象外とする。ただし、現在表示でColumn DnDを利用できない理由をfocusから確認できる振る舞いは本書で定義する。

## 2. 列並び替えの対象

列並び替えモードでは、対応するTable全体の列だけを並び替え対象として操作できる。

利用者が列並び替えモードを選択している間は、行の並び替え操作は開始しない。

並び替えが成立した場合は、Table全体の列順だけを変更する。セル内容、属性、装飾その他の保持すべき情報は変更しない。

## 3. 現在表示でColumn DnDを利用できない場合

Column DnDは、現在表示されているTableで各列が横方向の異なる位置として判別できる場合に利用できる。画面幅や表示方法の名称だけでは判断せず、利用者が現在見ている列配置を基準とする。

各セルが縦積みされる表示など、論理上のTable構造は維持されていても列ごとの横位置を判別できない場合は、ToolbarのColumn DnD入口を利用不可として表示する。対象Tableを選択した後に表示が変わり、列ごとの横位置を判別できなくなった場合も同じ状態へ更新する。Column Reorder Modeを選択中なら通常編集モードへ戻す。

利用不可の入口は単純に操作不能として理由を隠さず、PCではhoverまたはfocus、タッチ端末ではtouchにより次のメッセージを確認できる状態にする。

> 現在の表示では列のドラッグ並び替えを使用できません。列の並び替えはフォームから行えます。

利用不可の入口を選択してもColumn Reorder ModeやColumn DnDは開始しない。入口表示後にTableの配置が変わった場合も、DnD開始時の現在表示で列の横位置を判別できなければ、DnD中の表示、自動スクロール、Tableの更新を開始しない。

この制限はColumn DnDだけに適用する。Tableの論理構造が各操作の条件を満たす限り、Row DnDおよび行・列のReorder Formは引き続き利用でき、列のReorder Formを代替操作として使用できる。

一部の列だけが結合セルのため移動できない場合でも、Table全体の横方向の列配置を判別できるならColumn DnD入口は利用可能なままにする。個別の列を移動できない理由は4で定義する。

## 4. 結合セルにより移動できない列

`colspan`による結合範囲に含まれるため列単位では移動できない列からDnDを開始しようとした場合は、DnDを開始しない。

PCでは、列並び替えモード中にポインターがセルへ入った時点で、そのセルが属する列が移動可能か移動できないかを現在セルだけで予告する。移動可能なセルは控えめな操作可能表示と掴めるカーソルで示し、移動できないセルは控えめなグレー表示にして掴めるカーソルを表示しない。列全体を開始前から強調せず、利用者が今操作しようとしている位置だけで操作可否を確認できるようにする。

タッチ端末では、セルへ触れた時点で、そのセルが属する列の操作可否を現在セルだけで予告する。指を離しただけでは表示を終了せず、別のセルへ触れた場合はそのセルへ表示を移す。DnDを開始した場合は、開始前のセル表示を終了し、DnD中の列全体表示へ切り替える。並び替えモードの終了や操作対象Tableの変更など、現在の操作対象を維持できない状態になった場合は表示を終了する。

PCとタッチ端末の両方で、移動できない列から操作を開始しようとした位置の近くに、原因となる結合セルのTable領域と行・列位置を含むメッセージを表示し、どのセルが移動を妨げているかをその場で確認できるようにする。行・列位置は利用者向けの1から始まる番号で示し、原因セルがヘッダーまたはフッターにある場合はその領域も示す。原因セルが複数行または複数列を占有する場合はその範囲を示す。

例えば、本文1行目の1〜2列目を占有する結合セルが原因の場合は、次のように表示する。

- 日本語: `1行目の1〜2列目に結合セルがあるため、この指定では移動できません。`
- English: `A merged cell in row 1 spanning columns 1–2 prevents this move.`

移動不可メッセージは、利用者が内容を確認できる時間だけ表示し、数秒後に自動的に終了する。

`rowspan`だけを含み、列単位で移動してもTable全体の構造を壊さない列にはこの制限を適用しない。

このメッセージは、移動対象そのものを選べないためDnDを開始できない場合のフィードバックとする。DnD開始後に移動先が無効となる場合は、7の移動先の規則に従う。

移動できない列からDnDを開始しようとした場合は、Tableのデータを変更しない。

メッセージの表示に使う具体的なUI部品は本書では規定しない。

## 5. PCでのDnD

列並び替えモード中に、利用者がTable内のセルからドラッグを開始すると、そのセルが属する列を移動対象として扱う。

DnDが開始されたら開始前のセル予告表示を終了し、移動元の列位置を枠で示す。ドラッグ中は、移動中の列を独立した表示としてポインターへ追従させ、Table全体の有効な移動先となる列間に垂直の挿入線を表示する。

有効な移動先でドロップすると、その位置へ列を移動する。ドロップ直後は、指定した位置の列領域を短時間だけ枠で示し、どこへドロップしたかを確認できるようにする。

## 6. タッチ端末でのDnD

列並び替えモード中は、Table全体の列そのものを並び替え対象として操作する。

セルへ触れると、その時点で現在の操作対象として、そのセルが属する列の操作可否を現在セルだけで予告する。指を離してもDnDを開始していなければその表示を維持し、別のセルへ触れた場合は新しいセルへ表示を移す。

並び替えを開始していない通常操作では、Tableや編集画面を通常どおりスクロールできるようにする。開始前の操作可否表示は列全体の位置へ追従する表示を持たず、通常スクロールのための特別な表示制御は行わない。

セルからDnDを開始した後は、開始前のセル予告表示を終了し、移動元の列位置を枠で示す。移動中の列を独立した表示として指の移動へ追従させ、Table全体の有効な移動先となる列間に垂直の挿入線を表示する。

有効な移動先で操作を完了すると、その位置へ列を移動する。操作完了直後は、指定した位置の列領域を短時間だけ枠で示す。

## 7. DnD中の表示と移動先

DnD中は実Tableの列配置を動かさず、移動元の列位置を枠で示す。移動中の列は独立した表示として物理的なドラッグ位置へ追従し、どの列を移動しているかを確認できるようにする。

移動中の列は、元の列幅と表示対象セルの配置関係が不自然に崩れない範囲で表示する。大規模TableでもTable全体の全行を移動表示として再現することは要求せず、現在の操作で移動対象を識別するために必要な内容を表示する。Table内容ではないEditor専用の操作表示は移動中の列へ含めない。

移動中の列の背景越しに、移動先周辺の実Table内容を確認できるようにする。

現在の有効な移動先を、Table全体の列間に垂直の挿入線で示す。移動先が変わると、挿入線も現在の移動先へ移る。周囲列を押しのける表示や、移動先に空間を作る表示は行わない。

Table全体の構造を保てる位置だけを有効な移動先として扱う。結合セルなどのために移動するとTable全体の構造が成立しなくなる位置では、確定可能な移動先を示す挿入線を表示せず、並び替えを確定しない。

cancelまたは有効な移動先がない終了では、drop後の枠を表示しない。有効な物理drop直後は、最後に指定した移動先の列領域を短時間だけ枠で示す。この枠は「ここへdropした」位置を確認するための一時表示であり、Table更新の成功や更新後の列位置を保証する表示ではない。確定後の結果は、実際に反映されたTableの状態を正とする。

Column DnDの基本的な表示方針はiframe / non-iframeで分けない。どちらの環境でも、実Tableを押しのけず、移動中の列と垂直の挿入線を中心に現在の移動対象と移動先を示す。

## 8. 自動スクロール

Tableが画面内に収まらない場合でも、列の移動方向に沿って並び替えを続けられるようにする。

列のDnD中は、列の移動に必要な横方向だけを自動スクロールし、縦方向には自動スクロールしない。

DnDを開始していない通常状態では、この制限を適用せず、Tableや編集画面を通常どおりスクロールできるようにする。

## 9. 並び替え後の状態

列の並び替えが成立した場合、Table全体の列順だけを変更する。

セル内容がテキスト、画像、RichTextその他の内容であっても、列並び替えの扱いは変えない。セル内容そのものは変更せず、列の位置だけを変更する。

確定、キャンセル、安全な終了、Undoに関する共通の振る舞いは`reorder-v1-design.md`に従う。
