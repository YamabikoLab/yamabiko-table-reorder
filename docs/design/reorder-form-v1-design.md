# Reorder Form v1 基本設計書

## 1. 目的

本書は、Reorder Form（RF）v1について、利用者から見える画面、操作、状態、メッセージ、振る舞いを定義する。

RF固有の要件は`docs/requirements/reorder-form-v1-requirements.md`、DnDとRFに共通するReorder v1要件は`docs/requirements/reorder-v1-requirements.md`を正本とする。

データ保持、構造保持、Undo、対応Table Block、反映に時間がかかる場合、並び順が変わらない場合、反映を完了できない場合など、RFにも適用される共通要件に従う。

Keyboardのみでの操作、focus、announcement、支援技術への情報提供など、別要件として扱うアクセシビリティ設計は本書の対象外とする。

## 2. 基本方針

RFはDnDの補助操作ではなく、行または列を指定し、移動先となる行または列との位置関係を指定して直接並び替える独立した手段とする。

利用者は、対応するTableからRFを開始し、次を指定して並び替える。

- 行または列のどちらを並び替えるか
- 移動する行または列
- 移動先の行または列
- 行の場合は移動先の行の上または下、列の場合は移動先の列の左または右

利用者に示す位置番号は`1`から始める。

行では`tbody`の先頭行を`1`とし、列ではTableの左端の列を`1`とする。

「移動先の行」「移動先の列」として指定した位置番号は、並び替え前のTable上で指定した対象を表す。移動対象を取り除いたことで位置番号が変わる場合でも、指定した対象そのものとの位置関係を維持して並び替える。

たとえば2行目を5行目の下へ移動した場合、並び替え前に5行目だった行の直後へ移動する。

RFの利用者向け表示はWordPressの表示言語に従う。対応する翻訳がない場合はEnglishで表示し、YTR独自の言語切替UIは持たない。

## 3. RFの入口と他の並び替え手段との排他

対応するTableを選択している場合、TableのツールバーにRFの入口を表示する。

RFの入口は「行を並び替え」「列を並び替え」と同じ並び替え操作のまとまりに配置し、「列を並び替え」の隣に表示する。

入口には次のツールチップを表示する。

| 言語 | 表示 |
| --- | --- |
| 日本語 | フォームで並び替え |
| English | Reorder with form |

RFの入口を選択すると、そのTableを対象とするRFの入力画面を表示する。Tableと入力画面を同時に確認できる表示領域ではPopoverとして表示し、表示領域が狭い場合は画面下部の固定された入力画面として表示する。どちらの場合も、利用者がTableを確認しながら指定できることを優先する。

RFの入口も、`reorder-v1-design.md`で定義する共通の初回案内における並び替え入口として扱う。

行並び替えモードまたは列並び替えモードが有効な状態でRFを開始した場合は、現在の並び替えモードを終了してからRFを開始する。

RFの入力画面を表示している間は、同じTableに対する行DnDまたは列DnDを同時に有効にしない。

RFの入力画面を表示している状態でRFの入口を再度選択した場合は、Tableを変更せずRFを終了する。

RFの入力画面を表示している状態で「行を並び替え」または「列を並び替え」を選択した場合は、RFを終了してから選択した並び替えモードを開始する。

Popoverの外側を操作したことだけを理由としてRFを終了しない。

同じTableを選択して操作している間はRFを維持する。対象TableがEditor上の操作対象でなくなった場合はRFを終了する。

RFを終了した後に対象Tableを再選択しても、RFを自動的には再開しない。

RFを終了した場合、RF開始前に有効だった行または列の並び替えモードを自動的には再開しない。

## 4. RFの入力画面

RFの入力画面では、現在対象としているTableを並び替えるために必要な指定を行えるようにする。

画面構成と操作イメージは次のプレビューおよびプロトタイプを参照する。

![RF v1 UI preview](./images/reorder-form-v1-ui.svg)

- [RF v1 UIプロトタイプ](./prototypes/reorder-form-v1-ui.html)

プロトタイプは画面構成と操作感を確認するための参考資料とし、要件および正式な画面仕様は本設計書を正本とする。

入力画面には次のタイトルを表示する。

| 言語 | 表示 |
| --- | --- |
| 日本語 | フォームで並び替え |
| English | Reorder with form |

Tableと入力画面を同時に確認できる十分な表示領域では、入力画面を最初にTableツールバーのRF入口付近へPopoverとして表示する。利用者は入力欄、選択欄、ボタンなど直接操作する部品を除く入力画面上をドラッグして、Tableを確認しやすい位置へ自由に移動できるようにする。PCのポインター操作とタッチ操作のどちらでも移動できるようにする。

Popoverの移動中も入力内容や選択状態は変更しない。入力画面は画面外へ完全に移動できないようにし、移動後も操作可能な範囲を画面内に残す。

同じRF操作を続けている間にWordPress Editor側の再表示が発生しても、利用者が移動したPopoverの位置を維持する。RFを終了してから新しく開始した場合は前回の位置を引き継がず、Tableツールバー付近の初期位置へ戻す。

表示領域が狭く、PopoverとTableを同時に確認しにくい場合は、入力画面を画面下部へ固定して表示する。この表示ではPopoverの手動位置を適用せず、入力画面自体をドラッグして移動する操作も提供しない。

狭い表示の展開中は、入力画面を画面下部へ固定したまま、利用者が上端を上下へ操作して表示高さを調整できるようにする。これは入力画面を自由に移動する操作ではなく、RFを操作可能な状態のままTableと入力画面の表示割合を変える操作とする。

高さを小さくして内容が表示範囲へ収まらない場合は、入力画面内を縦方向へスクロールして、入力欄、選択肢、案内、確定操作、キャンセル操作へ到達できるようにする。高さ変更の操作領域と入力画面内の通常スクロール領域は分け、フォームのスクロールや入力操作を妨げないようにする。

狭い表示では入力画面を折りたためるようにする。折りたたんだ場合は入力欄と確定操作を隠し、現在指定している移動元、移動先、位置関係を短く確認できる表示を残す。再度展開すると、折りたたむ前の入力内容と選択状態をそのまま表示する。

折りたたみはTable確認のために入力内容を簡略表示する操作、高さ調整は展開状態のままTableとRFの表示割合を変える操作、内部スクロールは現在の高さに収まらない入力や操作へ到達する操作として、それぞれ別の目的で扱う。高さ調整を行わなくても、既定の高さ、内部スクロール、折りたたみによってRFの基本操作を行えるようにする。

同じRF操作中に十分な表示領域から狭い表示へ切り替え、その後ふたたび十分な表示領域へ戻った場合は、切り替え前に利用者が移動したPopoverの位置を復元する。狭い表示での折りたたみ状態と利用者が調整した高さも同じRF操作中は保持し、十分な表示領域では適用せず、再び狭い表示へ戻った場合に復元する。RFを終了して新しく開始した場合は、狭い表示を展開状態かつ既定の高さから開始する。

ソフトウェアキーボードなどによって利用可能な高さが小さくなった場合、展開状態の入力画面とTableを常に同時表示できることは必須としない。保持している利用者指定高さをそのまま表示できない場合は、現在操作可能な表示範囲へ一時的に収める。これは利用可能領域に応じた表示上の制限とし、利用者が指定した高さ自体は変更しない。利用可能な高さが再び広がった場合は、同じRF操作中であれば制限前の利用者指定高さへ戻す。

利用者が高さを小さくした場合やソフトウェアキーボードによって利用可能高さが不足した場合も、入力画面内をスクロールして必要な入力箇所と操作へ到達できるようにする。利用者が入力画面を折りたためば、Tableを確認できる状態へ退避できるようにする。

### 4.1 並び替える方向

「行」と「列」をラジオボタンで表示し、一つだけ選択できるようにする。

| 用途 | 日本語 | English |
| --- | --- | --- |
| 行方向 | 行 | Rows |
| 列方向 | 列 | Columns |

初期表示では「行」を選択した状態とする。

利用者が「行」または「列」を選択した時点で、選択した方向の入力フォームへ直ちに切り替える。別の確定操作を必要としない。

同じRF操作中は、行と列それぞれで入力した内容を独立して保持する。別の方向へ切り替えた後に元の方向へ戻った場合は、その方向で保持している入力内容を再表示する。

方向を切り替えた場合は、切り替え前の方向に対する構造上の移動不可表示や並び順が変わらないことを示す案内を引き継がない。再表示する結果は保持済みの古い判定を使わず、現在のTableに対して確認し直す。

### 4.2 行を選択した場合

次を指定できるようにする。

- 移動する行
- 移動先の行
- 移動先の行の「上」または「下」

各表示は次のとおりとする。

| 用途 | 日本語 | English |
| --- | --- | --- |
| 移動する行 | 移動する行 | Row to move |
| 移動先の行 | 移動先の行 | Target row |
| 移動先の上 | 上 | Above |
| 移動先の下 | 下 | Below |

「移動する行」と「移動先の行」は位置番号を数値で入力する。

「上」と「下」はラジオボタンで表示し、一つだけ選択できるようにする。

行番号の入力欄には、現在の`tbody`に存在する行の位置範囲と、有効な入力が整数であることを常に表示する。

行番号の入力欄で通常の増減操作を行う場合は、1行ずつ増減し、`1`未満または現在の`tbody`の行数を超える値へ進まない。

たとえば100行ある場合は、次のように表示する。不正な値を入力した場合でも、この有効条件の表示を維持する。

| 言語 | 表示 |
| --- | --- |
| 日本語 | 1〜100の整数を入力してください。 |
| English | Enter an integer from 1 to 100. |

「移動先の行」には、選んだ行の上または下へ移動することが分かる補足を表示する。

| 言語 | 表示 |
| --- | --- |
| 日本語 | 移動先の行の上または下へ移動します。 |
| English | Move the row above or below the target row. |

### 4.3 列を選択した場合

次を指定できるようにする。

- 移動する列
- 移動先の列
- 移動先の列の「左」または「右」

各表示は次のとおりとする。

| 用途 | 日本語 | English |
| --- | --- | --- |
| 移動する列 | 移動する列 | Column to move |
| 移動先の列 | 移動先の列 | Target column |
| 移動先の左 | 左 | Left |
| 移動先の右 | 右 | Right |

「移動する列」と「移動先の列」は選択肢から選択する。

列にヘッダーがある場合は、ヘッダー名と列番号をあわせて表示する。ヘッダー名は現在のTableに表示されている値をそのまま使用し、WordPressの表示言語によって翻訳または置換しない。表示言語に応じて変わるのは、YTRが付加する列番号部分とその書式だけとする。

たとえば3列目の見出しが`Product name`の場合は、次のように表示する。

| 言語 | 表示 |
| --- | --- |
| 日本語 | Product name（3列目） |
| English | Product name (Column 3) |

同じ見出しが複数ある場合でも列番号によって一意に識別できるようにする。

ヘッダーがない列またはヘッダーが空の列は、列番号で識別できる表示とする。

たとえば3列目の場合は、次のように表示する。

| 言語 | 表示 |
| --- | --- |
| 日本語 | 3列目 |
| English | Column 3 |

「左」と「右」はラジオボタンで表示し、一つだけ選択できるようにする。

「移動先の列」には、選んだ列の左または右へ移動することが分かる補足を表示する。

| 言語 | 表示 |
| --- | --- |
| 日本語 | 移動先の列の左または右へ移動します。 |
| English | Move the column to the left or right of the target column. |

### 4.4 初期表示

RFの入力画面を開いた直後は、未入力または未選択であることを理由とするエラーメッセージを表示しない。

必要な指定が揃うまでは「並び替え」を実行できない状態にする。

### 4.5 確定とキャンセル

入力画面には、指定した内容で並び替えを実行する操作と、RFを終了する操作を次の文言で表示する。

| 用途 | 日本語 | English |
| --- | --- | --- |
| 実行 | 並び替え | Reorder |
| キャンセル | キャンセル | Cancel |

キャンセルした場合はTableのデータを変更せず、RFを終了する。

並び替えを実行する場合は、指定内容が有効であり、Tableの構造上も成立することを確認してから反映へ進む。

## 5. 入力値の扱い

行の位置番号は、表示されている範囲内の整数だけを有効な位置として扱う。

次の指定は有効な位置として扱わない。

- 未入力
- 整数として解釈できない値
- `1`未満の値
- 現在存在する行数を超える値

未入力、未選択、または有効な位置として解釈できない値が残っている間は、「並び替え」を実行できない状態にする。

これらの入力状態について、入力内容に応じた動的なエラーメッセージは表示しない。行番号の入力欄に常時表示する現在の有効条件と「並び替え」を実行できない状態を組み合わせ、利用者が指定を修正する必要があることを認識できるようにする。

列は現在存在する列から選択するため、存在しない列番号や解釈できない文字列を利用者が直接入力する方式にはしない。Tableの変化などによって選択済みの列が現在の選択肢に存在しなくなった場合も、「並び替え」を実行できない状態にする。

有効に解釈できない指定または未選択の指定が残っている間は並び替えを反映せず、Tableのデータを変更しない。

入力値を内部でどのように検証、正規化、サニタイジングするかは、本書では規定しない。

## 6. Table構造上成立しない指定

入力された指定自体は有効であっても、結合セルのため、その行または列を指定した位置へ移動するとTableの構造を保持できない場合は並び替えを反映しない。

移動対象、移動先の行または列、上下または左右の指定が揃い、実際に並び順が変わる指定であることを確認した後に構造上成立しないことを判断できる場合は、「並び替え」を実行する前でも、その時点で移動できないことと理由を入力画面上に表示する。

移動を妨げる結合セルのうち最初に確認された1つについて、そのセルが占有する行と列の位置を表示する。行・列のどちらを並び替える場合でも、原因セルの位置を行番号と列番号の組み合わせで示す。

`tbody`にある原因セルの表示例は次のとおりとする。

| 条件 | 日本語 | English |
| --- | --- | --- |
| 1行・複数列 | 3行目の2〜3列目に結合セルがあるため、この指定では移動できません。 | A merged cell in row 3 spanning columns 2–3 prevents this move. |
| 複数行・1列 | 2〜3行目の4列目に結合セルがあるため、この指定では移動できません。 | A merged cell spanning rows 2–3 in column 4 prevents this move. |
| 複数行・複数列 | 2〜3行目の4〜5列目に結合セルがあるため、この指定では移動できません。 | A merged cell spanning rows 2–3 and columns 4–5 prevents this move. |

列の並び替えで原因セルがヘッダーまたはフッターにある場合は、本文行と誤認しないよう、その領域を明示する。たとえばヘッダーの1行目・2〜3列目であれば、ヘッダー内の位置であることが分かる文言を表示する。

複数の結合セルが移動を妨げる場合でも、一度に複数の理由を表示せず、最初に確認された1つだけを表示する。

利用者が移動対象、移動先、上下または左右の指定を変更した場合は、それまで表示していた構造上の移動不可メッセージを自動的に終了する。変更後の指定でも移動できないことを判断できる場合は、新しい指定に対応する理由を表示する。

Tableのデータは変更しない。

この場合は「並び替え」を実行できない状態にする。

## 7. 並び順が変わらない指定

移動対象と移動先の指定が有効であっても、並び替え後の順序が現在と変わらない場合はTableのデータを変更しない。

指定が揃った時点で並び順が変わらないことを判断できる場合は、「並び替え」を実行する前でも入力画面上で案内する。

| 言語 | メッセージ |
| --- | --- |
| 日本語 | この指定では並び順は変わりません。 |
| English | This selection won't change the order. |

並び順が変わらない指定と、結合セルによる移動不可条件の両方に該当する場合は、並び順が変わらないことだけを案内する。実際にTableを変更しない指定について、結合セルを理由とするエラーは表示しない。

利用者が指定を変更した場合は、それまでの案内を自動的に終了する。変更後も並び順が変わらない場合は、現在の指定に対応する案内を表示する。

この場合は「並び替え」を実行できない状態にし、不要なデータ更新やUndo履歴を作らない。

### 7.1 現在のTableで指定を確認できない場合

必要な入力が揃っていても、入力後にTableが変更されたなどの理由で、現在のTableに対して指定した並び替えを安全に確認できなくなった場合は並び替えを反映しない。

この場合は、内部の詳細な原因を個別に表示せず、次のメッセージを入力画面上に表示する。

| 言語 | メッセージ |
| --- | --- |
| 日本語 | 現在のテーブルでは、この並び替えを続行できません。テーブルの状態を確認して、もう一度お試しください。 |
| English | This reorder can't continue with the current table. Check the table and try again. |

Tableのデータは変更せず、「並び替え」を実行できない状態にする。

通常の入力欄や選択肢の更新によって、現在存在しない行や列の指定が未入力または未選択と同じ状態へ戻った場合は、このメッセージを表示せず、5節の入力状態として扱う。

### 7.2 入力状態と表示の優先順位

入力画面では、利用者が現在の指定をどう修正すればよいかを一意に判断できるよう、次の順序で状態を扱う。

| 状態 | 入力画面の表示 | 「並び替え」 |
| --- | --- | --- |
| 必要な入力が揃っていない、または有効な指定として扱えない | 動的なエラーメッセージは表示しない | 実行できない |
| 現在のTableで指定を安全に確認できない | 続行できないことを表示する | 実行できない |
| 並び順が変わらない | 並び順が変わらないことを表示する | 実行できない |
| 結合セルのため移動できない | 移動を妨げる結合セルの位置を表示する | 実行できない |
| 並び替え可能 | メッセージを表示しない | 実行できる |

この優先順位により、一つの指定に複数の状態が当てはまり得る場合でも、利用者には一つの結果だけを表示する。

## 8. 並び替えの反映

有効な移動対象、移動先の行または列、および上下または左右が指定され、Tableの構造上も成立する場合に並び替えを反映する。

行の場合は`tbody`内の行順だけを変更する。

列の場合はTable全体の列順だけを変更する。

セルの内容、属性、装飾その他の保持すべき情報は変更しない。

一回のRFによる並び替えは、一回のUndo操作で並び替え前の順序へ戻せるようにする。

## 9. 反映に時間がかかる可能性がある場合

並び替えの反映に時間がかかる可能性があると判断された場合は、反映を開始する前に、続行するか中止するかを選択できる確認を表示する。

確認を表示している間は、対象Tableで新しい行DnD、列DnD、またはRFを開始できない。

利用者が続行を選択した場合だけ反映を開始する。

中止した場合はTableのデータを変更せず、入力内容を保持したRFの入力画面へ戻る。

反映に時間がかかる可能性を判断する具体的な条件は、本書では規定しない。

## 10. 反映中

並び替えの反映を開始した後は、対象のTableを編集できない状態にする。

反映開始後も、対象Tableで新しい行DnD、列DnD、またはRFを開始できない。反映完了または失敗によって適切な状態へ戻るまでは、別の並び替え操作へ切り替えない。

対象のTable以外のブロックについては、通常どおり編集や操作を続けられるようにする。

反映が短時間で完了した場合は、不要な処理中表示を行わない。

反映が一定時間内に完了しない場合は、対象のTableで処理が続いていることを利用者が確認できるようにする。

表示例:

`反映中です。`

反映中であることを示す表示によって、対象Table以外のブロックの操作を妨げない。

一定時間の具体的な基準は、本書では規定しない。

## 11. 並び替え完了の確認

並び替えが完了したらRFの入力画面を終了し、通常のTable編集を妨げない短い完了通知を表示する。

完了通知には、正常に反映されたことを視覚的に確認できる控えめな成功アイコンを添え、次のメッセージだけを表示する。

| 言語 | メッセージ |
| --- | --- |
| 日本語 | 並び替えが完了しました。 |
| English | Reordering complete. |

完了通知のために利用者へ追加の確定操作や閉じる操作を要求しない。

並び替え後のTableは通常の編集状態で表示する。

## 12. 反映を完了できない場合

並び替えの反映を完了できなかった場合は、途中まで反映された状態を並び替え結果として残さない。

Tableは並び替え開始前の状態を保つ。

利用者には、並び替えを完了できなかったことを短いメッセージで知らせる。

表示例:

`並び替えを反映できませんでした。Tableは変更されていません。`

反映失敗後は、入力内容を保持したRFの入力画面へ戻し、利用者が指定を修正または再実行できる状態にする。

対象のTableも再び編集できる状態に戻す。

## 13. 対応Table Block

RFは、Reorder v1が対応する次のTable Blockで同じ操作方針とする。

- WordPress Core Table
- Flexible Table Block

Table Blockの違いによって、RFの基本的な入力方法や利用者に示す位置番号の意味を変更しない。
