# Reorder v1 要件定義書

## 1. 目的

Yamabiko Table Reorder 正式 v1 は、WordPress の対応する Table ブロックについて、利用者が Table の内容や構造を安全に保ちながら、行・列の順序を変更できることを目的とする。

本書は、DnD 固有の要件と、DnD・Reorder Form（RF）など複数の並び替え手段に共通して適用する Reorder v1 の要件を定義する。

RF 固有の要件は `reorder-form-v1-requirements.md` で別途管理する。

Quality Requirements は `reorder-v1-quality-requirements.md` で別途管理する。

具体的な画面構成、操作手順、表示方法、プログラム内部の実現方法は本書では扱わない。

Keyboard のみでの操作、focus、announcement、支援技術への情報提供など、アクセシビリティ上追加で必要な要件は別文書で定義する。

## 2. 対象範囲

正式 v1 の機能対象は、以下の Functional Requirements で定義する。

- 行 DnD / 列 DnD と対応する操作環境: `FR-01`, `FR-02`
- DnD と RF を含む Reorder v1 共通要件: `FR-03`〜`FR-09`, `FR-13`, `FR-17`〜`FR-22`
- DnD 固有の操作・表示要件: `FR-10`〜`FR-12`, `FR-14`, `FR-15`

RF 固有の能力は `reorder-form-v1-requirements.md` を正本とし、本書では重複して定義しない。

## 3. 要件

| ID | 項目 | 要件 | 理由 |
| --- | --- | --- | --- |
| FR-01 | 行の並び替え | 対応する Table の `tbody` の行を、PC およびタッチ端末から有効な別の位置へ DnD で移動できる。 | Table の内容を作り直さずに、利用者が行の順序を目的に合わせて変更できるようにするため。 |
| FR-02 | 列の並び替え | 対応する Table の列を、PC およびタッチ端末から有効な別の位置へ DnD で移動できる。 | Table の内容を作り直さずに、利用者が列の順序を目的に合わせて変更できるようにするため。 |
| FR-03 | データ保持 | 並び替え後も、セル内容の種類にかかわらず、セルの内容、属性、装飾その他の保持すべき情報を失わない。 | 並び替えを行っても既存の Table 内容や編集成果を損なわず、安心して順序だけを変更できるようにするため。 |
| FR-04 | 構造保持 | 結合セルなどを含む Table について、行の並び替えでは `tbody` 内、列の並び替えでは Table 全体の有効な構造を壊す並び替えを行わない。 | 結合セルを含む Table でも、並び替えによって Table として成立しない構造になることを防ぎ、安全に順序を変更できるようにするため。 |
| FR-05 | 無効操作 | キャンセルされた操作または成立しない並び替えでは、Table のデータを変更しない。 | 利用者が意図していない変更を残さず、安心して操作を中止できるようにするため。 |
| FR-06 | Undo | 一回の並び替えを、一回の Undo 操作で元に戻せる。 | 並び替えを通常の編集履歴として理解しやすくし、意図と異なる変更を容易に取り消せるようにするため。 |
| FR-07 | 編集との分離 | 通常の Table 編集と並び替え操作が意図せず競合せず、利用者が両者を明確に区別して利用できる。 | Table の内容編集と順序変更を取り違えることによる意図しない操作を避け、安心して双方を利用できるようにするため。 |
| FR-08 | 行・列の分離 | 行の並び替えと列の並び替えを明確に区別して利用できる。 | 利用者が変更する方向を取り違えず、意図した対象だけを並び替えられるようにするため。 |
| FR-09 | 機能の発見 | 初めて利用する人が、行・列を並び替えられることと、その利用方法を認識できる。 | 事前知識のない利用者でも並び替え機能の存在と使い始め方を理解し、必要なときに利用できるようにするため。 |
| FR-10 | 移動先の把握 | DnD 中、利用者が現在の移動先を確認できる。 | 操作中に並び替え結果を予測できるようにし、意図しない位置への移動を避けやすくするため。 |
| FR-11 | DnD の確定 | 有効な移動先への DnD が完了した場合だけ、Table の順序を更新する。 | 利用者の操作が成立した場合だけ変更を反映し、不確かな操作結果によって Table の順序が変わることを防ぐため。 |
| FR-12 | 通常スクロール | タッチ端末での並び替え機能によって、通常の Table または編集画面のスクロールを不必要に妨げない。 | 並び替え機能の存在によって、タッチ端末での基本的な閲覧・編集操作の使いやすさを損なわないため。 |
| FR-13 | 対応ブロック | WordPress Core Table と Flexible Table Block の両方で、本書の要件を満たす。 | 利用者が主要な対応 Table Block の違いを意識せず、同じ目的で並び替え機能を利用できるようにするため。 |
| FR-14 | 並び替え状態の認識 | DnD 開始時、利用者が DnD が開始されたことと現在の移動対象を視覚的に認識できる。 | 並び替え操作に入ったことと操作対象を明確にし、通常編集との取り違えや対象の誤認を避けるため。 |
| FR-15 | 移動の追跡 | DnD 中から確定後まで、利用者が移動対象を見失わず、移動対象と周囲の行・列の位置関係の変化を視覚的に追跡できる。 | 並び替えの途中から結果まで対象の位置変化を理解できるようにし、意図した移動になったか判断しやすくするため。 |
| FR-17 | 移動不可理由の認識 | Table の構造上成立しない並び替えを利用者が行おうとした場合、並び替えできないことと、その理由を認識できる。 | 操作できない状態を故障や反応不足と誤解せず、Table の構造に基づく制約として理解できるようにするため。 |
| FR-18 | 反映前の確認 | 並び替えの反映に時間がかかる可能性がある場合、利用者が反映を開始する前に、処理を続行するか中止するかを選択できる。 | 利用者が予期しない長時間の処理を開始することを避けられるようにするため。 |
| FR-19 | 反映中の認識 | 並び替えの反映開始後、処理が一定時間内に完了しない場合、利用者が反映処理中であることを認識できる。 | 処理の停止や不具合と誤認せず、反映が継続していることを判断できるようにするため。 |
| FR-20 | 反映中の編集範囲 | 並び替えの反映中は、対象の Table を編集できない。対象の Table 以外のブロックの編集や操作は妨げない。 | 反映中の Table に競合する変更が加わることを防ぎつつ、投稿全体の編集を必要以上に妨げないため。 |
| FR-21 | 並び順が変わらない指定 | 並び順が変わらない並び替えでは、Table のデータを変更しない。 | 実質的な変更がない操作によって不要なデータ更新や編集履歴を生じさせないため。 |
| FR-22 | 不完全な変更を残さない | 並び替えの反映を完了できない場合、Table に不完全な変更を残さない。 | 反映途中の状態によって Table の内容や構造が不整合になることを防ぎ、反映失敗時にも既存の編集内容を保護するため。 |

`FR-18`〜`FR-22` における、反映に時間がかかる可能性の判断条件、確認方法、一定時間の基準、反映中の表示方法、編集制御方法、無変化の判定方法、失敗時の復旧方法などの具体的な実現方法は Basic Design 以降で扱う。

## 4. RF 固有要件との分離

Reorder Form は、ドラッグを必要としない独立した並び替え手段として `reorder-form-v1-requirements.md` で定義する。

本書の共通要件は DnD と RF の双方に適用する。RF 固有の移動対象・移動先の指定、RF の開始、不正な指定の扱い、他の並び替え手段との排他などは RF 専用要件を正本とする。

RF の入力自体を有効に解釈できない指定は RF 固有要件で扱い、入力自体は有効に解釈できるものの Table の構造上成立しない並び替えは `FR-17` で扱う。

## 5. アクセシビリティ要件との分離

アクセシビリティ上追加で満たす必要がある要件は、本書とは別の要件文書で管理する。

RF はそれ自体がドラッグを必要としない並び替え手段であり、その能力はアクセシビリティ専用要件として重複定義しない。

主に次を扱う。

- Keyboard だけで必要な操作を完了できること
- 操作対象や操作状態を見失わないこと
- 必要な操作情報や結果を支援技術から確認できること
- focus の維持・復元
- 操作状態や結果の announcement

具体的なキー割り当て、focus の移動先、案内文、announcement の文言やタイミングなどは requirements より後の設計で定義する。

## 6. 対象外

本書では次を定義しない。

- 具体的な画面構成
- 並び替えを開始・確定・キャンセルする具体的な操作手順
- DnD の具体的な開始方法や判定方法
- handle などの具体的な UI
- 並び替え中の preview や移動先の具体的な表示方法
- RF の具体的な画面、入力部品、入力方法
- Keyboard の具体的な操作
- focus の具体的な移動先
- announcement や案内の具体的な文言・タイミング
- ソースコードや内部 architecture
- データ更新や描画の実装方式
- テストの実装方法
