# Reorder v1 要件定義書

## 1. 目的

Yamabiko Table Reorder 正式 v1 は、WordPress の対応する Table ブロックについて、利用者が Table の内容や構造を安全に保ちながら、PC およびタッチ端末から行・列の順序を変更できることを目的とする。

本書は、正式 v1 の最初の段階で最低限満たす DnD 要件を定義する。

具体的な画面構成、操作手順、表示方法、プログラム内部の実現方法は本書では扱わない。

Keyboard 操作、ドラッグを必要としない操作、focus、announcement、支援技術への情報提供など、アクセシビリティ上追加で必要な要件は別文書で定義する。

## 2. 対象範囲

正式 v1 の最初の対象は次とする。

- WordPress Core Table
- Flexible Table Block
- PC での行 DnD
- PC での列 DnD
- タッチ端末での行 DnD
- タッチ端末での列 DnD

## 3. 要件

| ID | 項目 | 要件 |
| --- | --- | --- |
| FR-01 | 行の並び替え | 対応する Table の行を、PC およびタッチ端末から有効な別の位置へ DnD で移動できる。 |
| FR-02 | 列の並び替え | 対応する Table の列を、PC およびタッチ端末から有効な別の位置へ DnD で移動できる。 |
| FR-03 | データ保持 | 並び替え後も、セル内容の種類にかかわらず、セルの内容、属性、装飾その他の保持すべき情報を失わない。 |
| FR-04 | 構造保持 | 結合セルなどを含む Table について、Table の有効な構造を壊す並び替えを行わない。 |
| FR-05 | 無効操作 | キャンセルされた操作または成立しない並び替えでは、Table のデータを変更しない。 |
| FR-06 | Undo | 一回の並び替えを、一回の Undo 操作で元に戻せる。 |
| FR-07 | 編集との分離 | 通常の Table 編集と並び替え操作が意図せず競合せず、利用者が両者を明確に区別して利用できる。 |
| FR-08 | 行・列の分離 | 行の並び替えと列の並び替えを明確に区別して利用できる。 |
| FR-09 | 機能の発見 | 初めて利用する人が、行・列を並び替えられることと、その利用方法を認識できる。 |
| FR-10 | 移動先の把握 | DnD 中、利用者が現在の移動先を確認できる。 |
| FR-11 | DnD の確定 | 有効な移動先への DnD が完了した場合だけ、Table の順序を更新する。 |
| FR-12 | 通常スクロール | タッチ端末での並び替え機能によって、通常の Table または編集画面のスクロールを不必要に妨げない。 |
| FR-13 | 対応ブロック | WordPress Core Table と Flexible Table Block の両方で、本書の要件を満たす。 |
| QR-01 | Performance | 大規模な Table でも、行・列の DnD を実用的に利用できる。 |

## 4. アクセシビリティ要件との分離

アクセシビリティ上追加で満たす必要がある要件は、本書とは別の要件文書で管理する。

主に次を扱う。

- Keyboard だけで並び替えを完了できること
- ドラッグを必要としない方法で並び替えを完了できること
- 操作対象や操作状態を見失わないこと
- 必要な操作情報や結果を支援技術から確認できること
- focus の維持・復元
- 操作状態や結果の announcement

具体的なキー割り当て、focus の移動先、案内文、announcement の文言やタイミングなどは requirements より後の設計で定義する。

## 5. 対象外

本書では次を定義しない。

- 具体的な画面構成
- 並び替えを開始・確定・キャンセルする具体的な操作手順
- DnD の具体的な開始方法や判定方法
- handle などの具体的な UI
- 並び替え中の preview や移動先の具体的な表示方法
- Keyboard の具体的な操作
- ドラッグを必要としない具体的な操作
- focus の具体的な移動先
- announcement や案内の具体的な文言・タイミング
- ソースコードや内部 architecture
- データ更新や描画の実装方式
- テストの実装方法
