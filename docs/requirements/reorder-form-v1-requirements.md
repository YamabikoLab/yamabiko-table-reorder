# Reorder Form v1 要件定義書

## 1. 目的

Reorder Form（RF）v1 は、利用者がドラッグを必要とせず、対応する Table の行または列を指定した位置へ直接移動できることを目的とする。

RF は DnD の補助機能としてではなく、独立した並び替え手段として扱う。

本書は RF v1 固有の Functional Requirements を定義する。

DnD と RF の双方に適用される Reorder v1 共通要件は `reorder-v1-requirements.md` を正本とし、本書では重複して定義しない。

具体的な画面構成、操作手順、入力部品、内部実装などの実現方法は本書では扱わない。

## 2. 対象範囲

RF v1 は、対応する Table の行および列を、ドラッグを必要としない方法で並び替える機能を対象とする。

行の並び替え対象は DnD と同様に `tbody` の行とし、列の並び替えは Table 全体の列を対象とする。

RF v1 は最初から行・列の両方を対象とする。

RF 固有の Functional Requirement には `RF-FR-XX` 形式の ID を使用する。`RF` は Reorder Form の要件スコープ、`FR` は Functional Requirement の種類を表す。

## 3. RF 固有要件

### RF-FR-01 移動対象の指定

**What**

> 利用者が、並び替えの対象とする行または列を一意に指定できる。

**Why**

> 意図した行または列を移動対象とし、別の行または列を誤って並び替えることを避けるため。

具体的な指定方法は Basic Design 以降で扱う。

### RF-FR-02 移動先の指定

**What**

> 利用者が、並び替え後に移動対象を配置する位置を一意に指定できる。

**Why**

> 意図した位置へ行または列を移動し、異なる位置へ誤って並び替えることを避けるため。

具体的な移動先の指定方法は Basic Design 以降で扱う。

### RF-FR-03 ドラッグを必要としない並び替え

**What**

> 利用者が、ドラッグを必要とせず、指定した移動対象を指定した位置へ並び替えられる。

**Why**

> ドラッグ操作が難しい場合や、離れた位置へ移動する場合でも、利用者が目的の並び順を効率的に実現できるようにするため。

具体的な操作方法は Basic Design 以降で扱う。

### RF-FR-04 並び替え完了の確認

**What**

> 利用者が、並び替えが正常に反映されたことを確認できる。

**Why**

> 並び替え操作が完了したことを利用者が判断できるようにするため。

具体的な確認方法は Basic Design 以降で扱う。

### RF-FR-05 不正な指定の扱い

**What**

> 移動対象または移動先として有効に解釈できない指定では、Table のデータを変更しない。また、利用者が指定を修正する必要があることを認識できる。

**Why**

> 不正な指定によって意図しない並び替えやデータ変更が行われることを防ぎ、利用者が正しい指定へ修正できるようにするため。

有効な指定と判断する具体的な条件や、入力値の検証・正規化・サニタイジングなど入力境界で必要な具体的な実現方法は Basic Design 以降で扱う。

### RF-FR-06 RF の開始

**What**

> 利用者が、対応する Table から RF による並び替えを開始できる。

**Why**

> 対象の Table に対して RF を利用するための入口を利用者が認識し、機能を開始できるようにするため。

具体的な入口の種類、配置、表示方法などは Basic Design 以降で扱う。

### RF-FR-07 他の並び替え手段との排他

**What**

> 同一の Table に対して、RF と他の並び替え手段を同時に有効にしない。

**Why**

> 異なる並び替え操作が競合し、利用者の意図しない状態や並び替えが発生することを防ぐため。

具体的な切り替え方法、既存の並び替え状態を終了するタイミング、UI の表示状態は Basic Design 以降で扱う。

## 4. Reorder v1 共通要件との関係

対応する Table Block、データ保持、構造保持、Undo、行・列の区別、成立しない並び替えの扱い、反映に時間がかかる場合の扱い、並び順が変わらない指定、反映を完了できない場合の扱いなど、RF と他の Reorder 手段に共通する要件は `reorder-v1-requirements.md` を正本とする。

`RF-FR-05` は、移動対象または移動先として入力自体を有効に解釈できない指定を対象とする。

入力自体は有効に解釈できるが Table の構造上成立しない並び替えは、共通要件 `FR-17`「移動不可理由の認識」の対象とする。

## 5. アクセシビリティ要件との関係

RF はドラッグを必要としない並び替え手段として定義するが、Keyboard のみでの操作、focus、announcement、支援技術への情報提供など、アクセシビリティ上追加で必要な要件は別のアクセシビリティ要件として管理する。

RF 固有要件には、具体的な Keyboard 操作や focus の扱いを重複して定義しない。

## 6. 対象外

本書では次を定義しない。

- 具体的な画面構成
- 具体的な操作手順
- 具体的な入力部品や入力方法
- 入力値の検証・正規化・サニタイジングの具体的な方法
- RF と DnD の具体的な切り替え方法
- 具体的な Keyboard 操作
- focus の具体的な移動先
- announcement や案内の具体的な文言・タイミング
- ソースコードや内部 architecture
- データ更新や描画の実装方式
- テストの実装方法
