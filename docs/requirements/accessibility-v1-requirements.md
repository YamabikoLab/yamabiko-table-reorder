# Accessibility v1 要件定義書

## 1. 目的

Accessibility v1 は、Yamabiko Table Reorder の主要な並び替え機能について、ドラッグ操作や視覚的な情報だけに依存せず、利用者が Reorder Form（RF）を通じて行・列の並び替えを行えることを目的とする。

本書では、WordPress.org へのプラグイン登録前に整備する Accessibility v1 Phase 1 の Functional Requirements を定義する。

行・列の並び替えそのものに関する共通要件は `reorder-v1-requirements.md`、RF 固有の機能要件は `reorder-form-v1-requirements.md` を正本とし、本書では重複して定義しない。

具体的な Keyboard 操作、focus の移動先、画面構成、案内文、支援技術への通知方法、その他の実現方法は本書では扱わない。

## 2. 対象範囲

Accessibility v1 Phase 1 では、RF を利用した行・列の並び替えについて、次のアクセシビリティ上の能力を対象とする。

- Keyboard のみで主要な並び替え操作を完了できること
- 操作中に利用者が操作位置を見失わないこと
- 操作部品や入力内容の意味と状態を支援技術から認識できること
- 入力上の問題を支援技術から認識できること
- 並び替え結果や移動できない理由を支援技術から認識できること

RF がドラッグを必要としない並び替え手段であること自体は `reorder-form-v1-requirements.md` を正本とし、本書では重複して定義しない。

Phase 1 は WordPress.org 登録前の Accessibility baseline とし、Accessibility 全体をこの Phase で完了させることを目的としない。

## 3. Accessibility v1 Phase 1 要件

### A11Y-FR-01 Keyboard による並び替え

**What**

> 利用者が、Keyboard のみを使用して RF による行または列の並び替えに必要な操作を開始から完了まで行える。

**Why**

> ポインター操作やドラッグ操作を利用できない場合でも、利用者が主要な並び替え機能を利用できるようにするため。

具体的なキー割り当てや操作順序は Basic Design 以降で扱う。

### A11Y-FR-02 操作位置の維持

**What**

> RF の利用中および並び替えの処理前後に、Keyboard を利用する利用者が操作位置を見失わず、必要な操作を継続できる。

**Why**

> 状態や表示の変化によって利用者が操作を続けられなくなることを防ぎ、一連の並び替え操作を完了できるようにするため。

具体的な focus の移動先、維持方法、復元方法は Basic Design 以降で扱う。

### A11Y-FR-03 操作部品と状態の認識

**What**

> 利用者が、RF の主要な操作部品について、その目的および現在の状態を支援技術から認識できる。

**Why**

> 画面上の表示を視覚的に確認できない場合でも、何を操作できるか、現在どの状態にあるかを理解して並び替えを行えるようにするため。

具体的な操作部品、支援技術への情報提供方法は Basic Design 以降で扱う。

### A11Y-FR-04 入力上の問題の認識

**What**

> RF への指定に修正が必要な場合、利用者が問題の発生と修正が必要な対象を支援技術から認識できる。

**Why**

> 視覚的なエラー表示だけに依存せず、利用者が問題のある指定を特定して修正できるようにするため。

入力値そのものの有効性や Table 構造上成立するかどうかの要件は、既存の RF および Reorder 要件を正本とする。

具体的なエラー表示、関連付け、案内方法は Basic Design 以降で扱う。

### A11Y-FR-05 並び替え結果と移動不可理由の認識

**What**

> 利用者が、並び替えが完了したこと、完了できなかったこと、または Table の構造上並び替えできないこととその理由を、視覚的な表示だけに依存せず認識できる。

**Why**

> 利用者が操作結果を確認し、必要に応じて次の操作や指定の修正を判断できるようにするため。

並び替え完了そのものは `RF-FR-04`、Table の構造上成立しない並び替えは `FR-17` を正本とし、本要件ではそれらの情報をアクセシブルに認識できることだけを追加で要求する。

具体的な通知方法、文言、通知するタイミングは Basic Design 以降で扱う。

## 4. 既存要件との関係

本書は、既存の Reorder / RF の機能要件をアクセシビリティの観点から置き換えたり再定義したりしない。

主な関係は次のとおりとする。

- RF を開始できること: `RF-FR-06`
- RF で移動対象・移動先を指定できること: `RF-FR-01`, `RF-FR-02`
- ドラッグを必要とせず並び替えられること: `RF-FR-03`
- 並び替え完了を確認できること: `RF-FR-04`
- 不正な指定を認識できること: `RF-FR-05`
- Table の構造上移動できない理由を認識できること: `FR-17`
- 反映中であることを認識できること: `FR-19`

本書では、それら既存の能力を Keyboard または支援技術から利用・認識するために追加で必要な要件のみを定義する。

## 5. Phase 1 対象外

Accessibility v1 Phase 1 では、次を対象外とする。

- Row DnD 自体の Keyboard 操作
- Column DnD 自体の Keyboard 操作
- RF の補助的なドラッグ操作に対する代替操作
- 操作対象サイズの全面的な監査
- 色やコントラストの全面的な監査
- zoom / reflow の全面的な監査
- motion の全面的な監査
- WCAG 2.2 AA 全項目への適合確認
- 複数の支援技術や OS の組み合わせを対象とした網羅的な検証
- WordPress 本体または利用する WordPress Component 自体のアクセシビリティ改善

これらは親 Issue #1046 の後続 Phase で必要性を評価する。

## 6. 本書で定義しないこと

本書では次を定義しない。

- 具体的な Keyboard 操作やキー割り当て
- focus の具体的な初期位置、移動先、復元先
- DOM 構造
- ARIA 属性や role
- 使用する WordPress Component
- announcement の実現方法
- announcement の具体的な文言やタイミング
- validation message の具体的な表示方法
- 画面構成や操作手順
- source code や内部 architecture
- state 管理や lifecycle の実装方式
- テストの実装方法

これらは Basic Design 以降で扱う。
